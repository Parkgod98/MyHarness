# 해결 방법 탐색

## 목적

현재 문제에 적합한 해결 방법을 폭넓게 발굴하고, 실제 조건에 맞춰 비교해 사용자의 의사결정을 돕는다.

알고리즘을 많이 사용하는 것이 아니라, 가장 합리적인 방법을 선택하는 것이 목표다.

## 실행 원칙

- 사용자가 명시적으로 요청할 때만 실행한다.
- AGENTS.md와 SPEC_GUIDE.md의 기존 원칙을 따른다.
- 현재 과제, 자료, SPEC, 코드, 환경과 제약을 먼저 확인한다.
- 사용자가 요청하지 않았다면 코드나 기존 문서를 수정하지 않는다.
- 특정 문제 유형, 기술 스택, 알고리즘을 미리 가정하지 않는다.

## 방법 탐색

1. 문제의 본질을 파악한다. 필수 제약, 개선 목표, 데이터 특성, 실행 환경, 검증 기준을 구분한다.

2. references/METHOD_CATALOG.md를 참고해 관련 알고리즘 계열을 찾는다.

3. 카탈로그는 탐색의 출발점이지 한계가 아니다. 문제에 더 적합한 알고리즘, 전문 기법, 최신 연구 방법, 하이브리드 접근이 있는지 추가로 검토한다. 필요한 자료에 접근할 수 있다면 근거도 확인한다.

4. 빠르게 적용할 수 있는 기본 방법과 경쟁력 있는 개선 후보를 비교한다. 방법별 적용 조건, 성능, 구현 비용, 위험, 검증 가능성을 살핀다.

5. 하이브리드 접근이 유리하다면 각 방법이 담당할 역할과 결합했을 때의 실질적인 이점을 설명한다.

6. 현재 환경과 가용 시간을 고려해 가장 합리적인 주력 방법, 대안, 전환 조건을 추천한다.

7. 중요한 선택은 사용자에게 맡긴다. 선택 후 구현을 요청하면 기존 SPEC과 검증 기준에 연결해 진행한다.

## 탐색 품질 기준

- 카탈로그에 없는 방법도 적극적으로 검토한다.
- 고급 알고리즘이라는 이유만으로 우선하지 않는다.
- 적용 조건이 맞지 않는 유명한 방법은 제외한다.
- 근거 없는 성능 향상이나 최적성을 주장하지 않는다.
- 비교가 필요하다면 공정한 실험 방법을 함께 제안한다.
- 해결책을 많이 나열하는 대신 실제로 경쟁력 있는 후보를 선별한다.
- 기존 방법과 차이가 없는 불필요한 복잡성은 피한다.

## 응답

결론부터 자연스러운 한국어로 설명한다.

- 문제의 핵심 특성
- 유력한 해결 후보와 선택 이유
- 후보별 장점, 한계, 구현 부담
- 추천 방법과 현실적인 대안
- 먼저 확인할 실험과 사용자 판단 사항

필요한 만큼만 설명하고, 세부 이론은 요청받으면 확장한다.

기본 결과는 채팅으로 제공한다. 별도 문서 작성이나 개발 중단을 강제하지 않는다.
